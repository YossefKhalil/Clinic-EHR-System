# AI import system — whole-system audit (2026-10-21)

Three read-only audits of the AI patient import (frontend glue, edge functions,
data layer) plus a runtime pass on the real review screen. This file is the
triage: what is broken, what was fixed in this pass, and what is still open.

**Headline:** the pipeline extracts correctly and the review screen works, but
the system was never finished. The most important finding is not a bug — it is
a missing half.

---

## 1. The import never writes a patient (P0, still open — this is M6)

`confirmImportNow()` only sets a note ("The commit step is part of the next
milestone"). There is no `commit` action in `import-job`, no RPC that inserts
into `patients`, and nothing writes `import_batches` / `import_batch_items` /
`import_rows.commit_result` / `import_jobs.commit_key`.

Everything the schema already anticipates exists but has no writer:
`patients.import_batch_id`, `import_batches`, `import_batch_items`,
`import_jobs.commit_key` (UNIQUE, for idempotency), `import_jobs.batch_id`,
`import_rows.commit_result`.

**Minimum implementation (M6):** one `SECURITY DEFINER` RPC that, in a single
transaction, re-runs the shared pipeline over the job's chunks (the browser's
verdict is untrusted), honours `dup.action` (`skip` → nothing, `fill` → UPDATE
the existing patient, `keep` → INSERT), maps the 17 registry fields to
`patients` columns, writes the batch + batch items (before/after, for undo),
stamps `import_batch_id`, and flips the job `review → committing → done`. The
client then calls `api.callJob('commit', { job_id, commit_key })` with a
per-job idempotency key.

Until that exists, **the feature cannot be used end to end** — which is worth
knowing before more UI polish.

## 2. Defects fixed in this pass

| Area | Defect | Fix |
|---|---|---|
| Provider | The OpenAI-compatible adapter (OpenAI, **Groq**) only read `message.content`; a reasoning model answers in `reasoning_content` → "no text" for a good answer. | `supabase/functions/_shared/llm/content-text.ts` — one shared `choiceText()` used by the Cloudflare **and** the OpenAI-compatible adapter (they had drifted). |
| Provider | Groq/OpenAI o-series reject `max_tokens` (HTTP 400); the body always sent `temperature: 0` and `max_tokens`. | `buildOpenAiBody()` now derives the body from the model: `max_completion_tokens` for reasoning models and for Groq, `reasoning_effort: 'low'`, no `temperature` for reasoning models. |
| Provider | `PROVIDER_TIMEOUT_MS` / `PROVIDER_MAX_ATTEMPTS` in `limits.js` were never read by the adapters. | Threaded through `buildProvider()` → the adapters. |
| Extraction | The repair call renumbered its documents from 1, so a repaired document **overwrote another patient's row** (both rows got the same record). | `run-chunk.js`: `mergeRepairedDocuments()` re-indexes the repaired documents onto the free positions of the original parse. Regression test added. |
| Extraction | A chunk that had to be split kept its partial rows, and the children re-extracted the same lines → every patient twice. | The parent's rows and tray entries are deleted before the children take over. |
| Extraction | Every DB write in the chunk-result path ignored its error: a chunk could be marked `done` with **no rows stored** and no message. | All writes check `{ error }`; a failed row write marks the chunk `failed` with `PERSIST_FAILED`. |
| Extraction | The lease (90 s) was shorter than the work it protected (chain × attempts × 120 s) → the same chunk processed twice, billed twice. | `leaseSecondsFor()` derives the lease from the chain length, capped by `LEASE_SECONDS_MAX`. |
| Job | A cancelled job was flipped back to `review` by the in-flight pump. | `settleToReview()` never overwrites a cancellation. |
| Job | Hitting the daily token cap left the job in `extracting` forever (and it kept one of the two job slots). | The daily cap settles the job to `review` with the banner. |
| Job | "Retry chunk" re-ran *any* chunk, doubled the tray entries and billed the provider again. | Only `failed` chunks can be retried; their rows and tray entries are deleted first. |
| Job | The provider's raw error body (which can echo the request, i.e. patient data) was stored in `import_jobs.config` and echoed to the browser. | Still open (P2) — flagged below. |
| Data | `import-cleanup` nulled the chunk payloads of jobs that were **still in review**; the review then re-ran the pipeline without the source lines, blanked every field and **wrote that destruction back to the database**. | Cleanup only purges terminal jobs; `revalidate()` skips a chunk whose payload is gone. |
| Review | Every row was labelled "Manual": the client looked for `row.source_id`, a column `import_rows` does not have. | The source is resolved through `row.chunk_id → chunk.source_id → import_sources.name`. |
| Review | The **Import button could never be enabled**: the "Row looks good" button was only rendered for row-level issues, while the gate counted field-level warnings. | `hasRowIssues()` now means "error or unacknowledged warning" (any field). |
| Review | `$root.navigate(...)` threw: Alpine's `$root` is the import wizard, not the app → "Back to patients" and "Open settings" were dead buttons. | The app method is resolved through the parent scope. |
| Review | Rows were ordered by `import_rows.seq`, which is unique **per chunk** only → the files interleaved and the row numbers repeated. | The rows are ordered by (chunk, seq) in the client, and the number shown is the position in the job. |
| Review | Paging read `import_rows` ordered by a non-unique column → rows duplicated and dropped above 500 rows. | The order has a unique tiebreaker (`id`) and a matching index `(job_id, seq, id)`. |
| Review | Undo restored the **stale** version → every later save failed with `SAVE_CONFLICT` forever. | `applySnapshot()` keeps the live version. |
| Review | The duplicate partner was resolved with a pipeline record index against the stored row numbers → the wrong patient when a record had been rejected. | The index is a hint; the partner is confirmed by the duplicate group. |
| Review | The chart rendered **both** tables and a full 17-field record panel per row: ~100 000 DOM nodes for 500 patients, and a frozen tab. | The mode containers and the expanded row are `<template x-if>`: one table at a time, one record panel. 5 rows → 1 538 DOM nodes. |
| Review | Elements with `x-show` **and** a Bootstrap display utility (`.d-flex`) could never be hidden (`!important` beats Alpine): an empty red error bar, the "removed by you" strip and the warning strip were always visible. | The utilities were moved to an inner element, and a global `[x-show][style*="display: none"]{display:none!important}` guard makes the mistake harmless. |
| i18n | The reader errors were looked up under `importAgent.error.*` but live under `importAgent.reject.*` → raw keys in the file list. | `fileErrorLabel()` + the missing `PARSE_FAILED` message. |
| i18n | Seven server codes had no message (`CHUNK_STATE`, `CHAIN_EMPTY`, `PROVIDER_IN_USE`, `TEST_FAILED`, `INVALID_*`) and the chunk failure codes were never shown at all. | The keys are added and the review screen now lists the failed chunks with the provider's reason and a retry button. |
| Review | `init()` ran twice (`x-init="init()"` + Alpine's magic method). | The `x-init` attribute is gone. |
| Review | The file-error and dead-code surface: the row drawer, the confirmation modal and the bulk modal are markup that nothing can open. | Still open (P2) — the record panel is now the only surface; the dead markup is queued for removal. |

Tests: 408 pass (was 398) — new regression tests for the repair-call index
collision, the reasoning-model answer, the Groq body, the purged payload, the
undo version and the duplicate skip.

## 3. Still open (ordered by risk)

**P0**
1. The commit path (section 1) — the feature is not usable end to end.
2. `supabase/migrations/` does not exist: `schema.sql` is re-applied as-is, so
   a column can never be *changed* or *dropped* on the live database, and the
   two CI workflows (schema, functions) run concurrently with no ordering — a
   function can be deployed before its migration exists (`groq_key_encrypted`,
   `model_chain`).

**P1**
3. Autosave is one HTTP PATCH per row, sequential, not awaited in four call
   sites, with no retry: a bulk fill of 200 rows issues 200 requests, and one
   conflict drops the rest while the screen already shows the new values.
4. The pump can exceed the function's wall clock (3 chunks × 3 attempts ×
   120 s × 8 chain entries ≈ 48 min inside one invocation) and the client
   gives up on the first error without a retry.
5. `import_jobs.config` is read-modify-written as a whole document → a lost
   update between two tabs.
6. The job's frozen model chain is ignored: the live admin settings decide
   mid-job, so the job record can lie about which provider handled it.
7. `patients.section` is nullable and the job's default section is never
   applied → a patient without a section is invisible to every section user.
8. The persisted `import_rows.status` is the pipeline verdict, not the
   reviewer's decision: a resolved duplicate stays `status='error'` in the
   database.
9. The review-edit guard trigger only enforces a column allow-list: a row can
   be marked `ready` with no name and an error-severity issue still listed.
10. No index serves the review load's hot query (fixed in this pass) and
    `check:registry` only compares column *names* — it cannot see a type,
    nullability or policy drift.

**P2**
11. The provider's raw error body is persisted and echoed to the browser.
12. `import-extract/` is a shared module inside `functions/` — a deploy trap
    (`supabase functions deploy --all` fails on it).
13. The `import_settings` row has no writer; the limits override is inert.
14. The "test provider" action posts the key to an admin-supplied `http://`
    base URL; the retention/no-training posture is only declared for
    OpenRouter.
15. Dead code: the row drawer, the confirmation modal, the bulk modal, the
    preview step (`preview.js` + `chunker.js`), the undo/redo stack, the
    debounced-typing autosave, `saveRows`, `fetchSeenHashes`, `hashWarning`.
16. The marital-status options are still English in the Arabic UI
    (`enumOptions()` capitalises the English value instead of using the
    Arabic label of the enum snapshot).

## 4. How to look at the screen without a real import

`http://127.0.0.1:3000/?mock=review` (and the same path on the deployed
preview) renders the real review screen with mock rows: no login, no network,
no patient data. It is the fastest way to compare the screen against
`public/mockups/import-ux.html` and to take a screenshot — the browser
screenshot tool needs a visible desktop window, the mock route does not.

Switch with `?mock=review`; the mode toggle, the record panel, the duplicate
panel, the strips and the sticky bar all work on the mock data.
